# 0024 — Conversations are collected by position, masked twice, and written as notes

- **Status**: accepted
- **Date**: 2026-11-05
- **Spec**: D-44; builds on D-06, D-08, D-09, D-10; answers Q-23, Q-24 (in part), Q-27

## Context

The heart of Mnemarr is one chain: assistants talk, a collector gathers it, Mnemarr keeps it as a memory, any assistant asks for it over MCP ([the roadmap](../ROADMAP.md)). Until now only the last link existed. ADR 0005 decided the collector and its guarantees; this one decides how the first slice of the chain is built, with no language model in the loop, so that it costs nothing per conversation and can be in production early.

## Decision

1. **The collector sends lines, by position.** It reads the conversation files of Claude Code (`~/.claude/projects/*/*.jsonl`, the files of sub-agents left out), keeps for each file how many lines and bytes it has sent, and sends the new complete lines in batches (500 lines or 3 MB at most) with the position of the first one: `POST /api/v1/ingest/conversations`, `{format, machine, application, session, from, lines[]}`. A line still being written waits for the next pass. The position file is also its queue: a line that did not go is still in the conversation file, so nothing is lost when the server is away, and the collector can be stopped at any time. The application is the last folder of the `cwd` that a line of the conversation says (the name of the project folder when none does). A line that is too long to be a message is replaced by a marker, so that positions do not move.
2. **The server answers with its own position.** It takes the lines that start at its position or before it (the overlap is skipped), refuses to leave a hole, and always answers `{next, accepted}`. A collector that is told another position than it expected goes there and sends from there: sending the same batch twice changes nothing, and a collector that lost its memory catches up without a conflict.
3. **An ingest-only key.** The `Collector` role holds only `ingest.write`: such a key sends conversations and reads nothing, not even the machines list. `GET /api/v1/ingest/machines` (system read) tells which machines sent something and when, so that an agent that is silent can be told from one that has nothing to say (a heartbeat that says it is alive while idle is not built yet).
4. **Masked twice, by the same rules.** The collector masks secrets before a line leaves the machine; the server masks again before it stores or indexes anything (D-10), and refuses a line it could not check. The rules are the same on both sides (private keys, GitHub and Slack tokens, `sk-` keys, AWS keys, JWTs, bearer tokens, credentials in addresses, `PASSWORD=`-like assignments), applied to the line as it is written in JSON, and a file of samples (`tests/masking/samples.json`) is run by the tests of both so that two engines written by hand do not drift (Q-27). Rules as versioned data served by the API, and rules configured in the interface, are not built.
5. **Raw lines are kept apart from the notes, outside Git.** Masked, compressed, under `<data>/raw/<machine>/<session>/`, one file per batch named by the position of its first line, so that a batch sent again writes the same file (ADR 0004; closes Q-23: compressed files, not rows). They are what a better reader will read again. Retention (Q-10) is not built.
6. **A conversation is a note.** The server writes one Markdown note per conversation, `<application>/<day>-<session>.md`, in a source of the new kind **`Conversations`**: front matter (tags `conversation` and the application, the format, the machine, the session, the start), a title taken from what was first asked, and each turn under its own heading. Only what was said is kept: the calls of tools, their results and the thinking are not the conversation, and are the bulk of it. The text of a turn is in a code fence longer than any run of backticks inside it, so that what a conversation contains (headings, `[[links]]`, `#tags`) never becomes the structure, the links or the tags of the note. The note is rewritten from the raw lines at each batch (idempotent), and read into the index at once, under the lock of the source: an assistant finds what was said a moment ago.
7. **The `Conversations` source is Mnemarr's.** Created the first time a collector sends something, in `<data>/conversations` (always allowed as a folder of a source, not listed among the operator's roots), one at most, owned by Mnemarr (nobody declares, edits or forgets it by hand), never written by people or assistants over the notes API (the kind refuses it, like application documentation). It is a source like any other for reading: the tree, the reader, the search, the MCP tools, a key limited to some sources.

## Consequences

- Any assistant connected over MCP finds the conversations of every machine with the existing `search`, `list_notes` and `read_note`, filtered by `topic` (the application).
- A machine that sends nothing is visible by the age of its last conversation only; a heartbeat is the next step (the production vertical).
- The memory vault stays for consolidated notes (D-14): conversations are not in it, and not in Git.
- The format of Claude Code files is not a contract: a line that is not what was expected is skipped. Another assistant is another `format` behind the same endpoint.
- Not here: consolidation of conversations into durable notes (it needs the assistant runner and a decision on what pays for it), vectors, retention, the install command, the service files for Linux and Windows, a read key per machine (Q-26), a compatibility policy for older collectors (Q-28: the contract is additive within v1).
