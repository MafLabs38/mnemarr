# 0027 — Machines join with a code, hold a key bound to their name, and say they are alive

- **Status**: accepted
- **Date**: 2026-11-05
- **Spec**: D-47; builds on D-45 and [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) (§3 enrolment, §5 heartbeat and states); answers the findings of the four review rounds of vertical 1 that [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) had accepted as a known limit (a key writing under any machine name)

## Context

[0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) decided that a machine is enrolled by a one-time code and watched by a heartbeat. This record fixes the parts of it that the first vertical to build it has to settle: the shape of a machine, of a code, of the exchange, of the heartbeat, and the states the page tells. It is the first half of the collector as a service; installing the program as a service on each system and the configuration from the server come after.

## Decision

1. **A machine is an entity.** One row per machine name: its **kind** (`always-on` or `intermittent`), the service account that sends for it, when it was enrolled, when it was last seen, the version of its collector, what it still had to send, the error of its last pass, and when it was revoked. The name follows the rule of the ingest (letters, digits, dots, hyphens, underscores, up to 50 characters; the ingest accepts up to 100 for the name of a session). The conversations a machine sent are counted from the conversations, not stored twice.
2. **An enrolment is a code with a state.** `pending` (asked for, not yet approved), `approved` (a person said yes), `used`, `rejected`, `expired`. A code is 12 characters from an alphabet without look-alikes (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`), written `XXXX-XXXX-XXXX` (about 60 bits), kept as a hash, shown once. It is bound to a machine name and a kind. It lives **15 minutes from its approval**; a request nobody approves expires after 24 hours. It works once.
3. **Two ways to ask, one way to approve.** A person who holds `collectors.manage` (an `Admin`) adds a machine in the interface: that is a request approved on the spot, and the code is shown once with the command to run. An assistant that holds `collectors.request` (the `Assistant` role, and `Admin`) calls the MCP tool `request_collector_enrolment`: that is a request left `pending`, answered with the command and the code; the code is of no use until a person with `collectors.manage` approves it in the interface. An approver can also reject. Mnemarr executes nothing on the machine.
4. **The exchange is anonymous and guarded by the code alone.** `POST /api/v1/ingest/enrol` with `{code, machine}`, under the ingest prefix (the one a proxy may publish without a single sign-on for the collectors, Q-28). If the code is approved, unexpired, unused and bound to that machine, the server creates the service account of the machine (role `Collector`, name `collector-<machine>`) or reuses it, **revokes the keys the account had** (a machine that enrols again replaces its key: a person approved it), creates a key, marks the code used, and answers `{key, machine, kind}` once. A wrong, expired, used or unapproved code gets the same answer, so that nothing says which. Failed exchanges are counted for the whole server: after ten in a minute every exchange answers 429 until the minute is over, so that a code cannot be guessed (60 bits, 15 minutes, once, ten tries a minute: out of reach).
5. **A key is bound to its machine, and the ingest refuses the rest.** The account of an enrolled machine is the one in its row. A batch that names another machine is refused with 403 and a problem that says which machine the key belongs to. A `Collector` account that belongs to no machine (a hand-made one) is refused too, unless the setting `Ingest:RequireEnrolment` is turned off, which is for a sandbox and for the day before every machine is enrolled; the default is on. This closes the limit that [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) §3 accepted.
6. **The heartbeat.** At the end of every pass, even a pass that sent nothing, the collector calls `POST /api/v1/ingest/heartbeat` with `{version, pendingLines, error, paused}` (`error` is null or a short sentence, with no path and no content). The server takes the machine from the key. A batch also counts as a sign of life. A heartbeat from a key of no machine is refused.
7. **The states are computed from facts, with two settings.** `Collectors:OnlineWithinMinutes` (5) and `Collectors:SilenceAfterMinutes` (30). From the facts (revoked or not, last seen, kind, the last error): **refused** (the key was revoked), **waiting** (enrolled, never seen), **failing** (the last pass reported an error), **online** (seen within the first setting) or **paused** (seen within it, and a person asked it to be quiet), then for an `intermittent` machine **away** (asleep or off: not an error), and for an `always-on` machine **silent**. A pure function of those facts and the clock, so that it is tried without a clock.
8. **The health is one mechanism.** A readiness check `collectors` (D-13, F-HLT-01) is degraded, with a reason code, when an `always-on` machine has been silent longer than the second setting (`collector-silent`) or reports an error (`collector-failing`). An `intermittent` machine never degrades it. The page and the check share the one function of §7.
9. **Revoking** a machine disables its account and revokes its keys; the row stays, as **refused**, so that what it wrote can be found and the name is not taken again without a person. A revoked machine can then be **removed from the list** (`POST /api/v1/collectors/{machine}/forget`, only when it is revoked): its name is free again and what it sent stays. A machine that sent conversations without ever being enrolled is shown as **unenrolled**.
10. **The rights.** `collectors.manage` (adds, approves, rejects, revokes; `Admin` only) and `collectors.request` (asks over MCP; `Assistant` and `Admin`). Seeing the machines needs `conversations.read`, as before (ADR 0024 §3).
11. **The collector** gains `enroll --server URL --code CODE [--machine NAME]`: it exchanges the code, writes the key to a file only its user can read and a small bootstrap file (server, machine) beside it, and `run` and `once` find them without flags. The key is also accepted from the environment or a `--key-file`. It sends the heartbeat at the end of each pass; a refusal of the key is reported as such and does not stop the loop.

12. **A machine installs by one line, served by Mnemarr.** Adding a machine shows one line to paste, for each system this Mnemarr has a program for: `irm '<server>/api/v1/ingest/install.ps1?code=…&machine=…' | iex` (PowerShell) or `curl -fsSL '<server>/api/v1/ingest/install.sh?code=…&machine=…' | sh` (Linux, macOS). The installer is a text that the server writes for that code and machine; it downloads the program from `<server>/api/v1/ingest/download/<system>`, verifies its SHA-256 (computed by the server from the file it serves), joins the machine with the code and starts collecting. It needs no administrator rights and nothing installed first. Both endpoints are anonymous, under the ingest prefix: the program is the same for everyone and holds no secret, and the code is of no use unless a person approved it. What is put into an installer is checked first (a code of the alphabet, a machine name, an address of plain characters), so that it cannot end a string or add a command. The programs are the files of `Collectors:DownloadFolder` that the code names (one per system), and nothing else of the folder; the image carries them, a developer mounts a folder. A Mnemarr with no program gives no line and says so. The address in the line is the one set in `Collectors:PublicUrl`, or the one the request came with.
13. **Plain HTTP is a choice that is said.** When the address in the line is `http://`, the page and the answer of the MCP tool say that the key will travel without encryption, and the installer passes `--allow-insecure-http` to the collector, which keeps it (in its small file) and warns each time it starts. Without that flag the collector accepts `http://` only for the machine itself. A Mnemarr served over HTTPS shows no such warning and the flag does not exist in its lines.

14. **The installer installs, and hands the window back.** `mnemarr-collector install` makes the collector start with the session of the user and starts it now, in the background, with no window; the installer ends there. On Windows the entry is in the user's own list of programs that start with their session (`HKCU\...\Run`, which Task Manager and Settings show and let the user switch off: nothing hidden, no administrator rights); on Linux it is a unit of the user's own systemd, at a low priority, restarted if it fails. `start`, `stop`, `status` and `uninstall` do what they say (`uninstall` leaves the machine joined). One collector runs for a machine: the running one holds a lock in its folder, and a second leaves it be. What it says goes to a log in the same folder, started again when it grows past a megabyte. The icon in the notification area and the pause come next (roadmap 2b).

15. **A download that already knows its parent.** For Windows the page also offers a button, **Download**, next to the line: the file `mnemarr-collector-<machine>.exe` is the program with a small setting written after it (the address of this Mnemarr, the name of the machine, the code, and whether plain HTTP was accepted): `[program][json][length: u32, little endian]["MNMRCFG1"]`. The program does not look at what follows it. Opened with nothing to say, it sees its setting and sets itself up: it puts a copy of itself, without the setting, in its folder, joins the machine with the code, and has the copy installed (§14). Opened with anything to do (`status`, `--version`), it is the program as ever. Mnemarr writes the setting at each download, for one machine and one code, from the unchanged program of the image or the CI: nothing is recompiled, the file is not kept (`Cache-Control: no-store`) and is named after the machine. The line stays for terminals and assistants. A file downloaded by a browser is not executable on Linux and macOS, so the button is for Windows only. While the program is not signed, Windows says its publisher is unknown (SmartScreen): the page says what to choose, and a code-signing certificate, applied before the setting is written (a signed program with data after the signature is checked with care), is the way to remove the warning.

16. **The person can pause it, and sees that it runs.** On Windows the collector shows an icon in the notification area while it runs: a line drawing of a brain that is green when all is well, orange when paused, red when Mnemarr cannot be reached or something is wrong (grey-blue while it starts), with a menu: the state in words, *Pause for one hour*, *Pause until I resume*, *Resume*, *Open Mnemarr*, *Quit the collector*. A pause is a file in the folder of the collector (`paused`: `forever`, or the moment it ends), so that the icon, `mnemarr-collector pause [--minutes N]` and `resume`, and the running collector all agree, and it survives a restart. A paused collector reads and sends nothing, and still sends its heartbeat, marked paused: Mnemarr tells the machine **paused**, never silent, and a pause is never an alert, even for an always-on machine. A pause that is not said any more (the machine is off) is no longer shown: the usual states apply. The icon is drawn by the thread that listens to the menu; the collecting is in another, and goes on when no icon can be made (a session with no taskbar). `--no-tray` keeps it away. The icon uses two new dependencies, `tray-icon` and `tao` (Windows only, for now): a decision of the pull request. macOS and Linux with a screen come later.

## Consequences

- A leaked key writes only under the name of its machine, and what a revoked key wrote can be found: the account is recorded on each conversation (ADR 0024 follow-up) and the machine is a row.
- The ingest endpoint can be exposed (vertical 3) without the risk the reviewers raised four times.
- An existing hand-made `Collector` account stops working at the next start, unless `Ingest:RequireEnrolment` is off. It is written in the release notes and in `docs/collector.md`.
- A code is pasted inside a line, not typed: the person has nothing to install, copy by hand or tunnel.
- The limit on wrong codes is for the whole server, so whoever can reach the endpoint can keep a person from joining a machine for a minute by sending ten wrong codes: a nuisance, not a way in, and the price of not trusting an address behind a proxy.
- Not here: installing the program as a service (the next vertical), the configuration from the server, a second key to read memory (Q-26), the notification of an alert (Portarr raises it, Q-38).
- An assistant's request may not name a machine that is enrolled and not revoked: the code would give that name, and its key, to whoever holds it. A person who manages the collectors replaces a machine by adding it again.
- A program that carries a code (the **Download** button) is written only for a code a person approved for that machine, and is streamed from its file: the endpoint is anonymous and the program is several megabytes.
- The programs are served from `Collectors:DownloadFolder`. Until the image carries them (a later vertical), an operator fills the folder from the release artifacts of the CI; without them the page offers no line and no button.
- The check of a code before a download counts a wrong code like the exchange does, for the whole server: a crawler that fetches download links with wrong codes can keep a person from joining for a minute, the same accepted nuisance.
