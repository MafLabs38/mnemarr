# 0027 — Machines join with a code, hold a key bound to their name, and say they are alive

- **Status**: accepted
- **Date**: 2026-11-05
- **Spec**: D-47; builds on D-45 and [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) (§3 enrolment, §5 heartbeat and states); answers the findings of the four review rounds of vertical 1 that [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) had accepted as a known limit (a key writing under any machine name)

## Context

[0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) decided that a machine is enrolled by a one-time code and watched by a heartbeat. This record fixes the parts of it that the first vertical to build it has to settle: the shape of a machine, of a code, of the exchange, of the heartbeat, and the states the page tells. It is the first half of the collector as a service; installing the program as a service on each system and the configuration from the server come after.

## Decision

1. **A machine is an entity.** One row per machine name: its **kind** (`always-on` or `intermittent`), the service account that sends for it, when it was enrolled, when it was last seen, the version of its collector, what it still had to send, the error of its last pass, and when it was revoked. The name follows the rule of the ingest (letters, digits, dots, hyphens, underscores, up to 100 characters). The conversations a machine sent are counted from the conversations, not stored twice.
2. **An enrolment is a code with a state.** `pending` (asked for, not yet approved), `approved` (a person said yes), `used`, `rejected`, `expired`. A code is 12 characters from an alphabet without look-alikes (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`), written `XXXX-XXXX-XXXX` (about 60 bits), kept as a hash, shown once. It is bound to a machine name and a kind. It lives **15 minutes from its approval**; a request nobody approves expires after 24 hours. It works once.
3. **Two ways to ask, one way to approve.** A person who holds `collectors.manage` (an `Admin`) adds a machine in the interface: that is a request approved on the spot, and the code is shown once with the command to run. An assistant that holds `collectors.request` (the `Assistant` role, and `Admin`) calls the MCP tool `request_collector_enrolment`: that is a request left `pending`, answered with the command and the code; the code is of no use until a person with `collectors.manage` approves it in the interface. An approver can also reject. Mnemarr executes nothing on the machine.
4. **The exchange is anonymous and guarded by the code alone.** `POST /api/v1/ingest/enrol` with `{code, machine}`, under the ingest prefix (the one a proxy may publish without a single sign-on for the collectors, Q-28). If the code is approved, unexpired, unused and bound to that machine, the server creates the service account of the machine (role `Collector`, name `collector-<machine>`) or reuses it, **revokes the keys the account had** (a machine that enrols again replaces its key: a person approved it), creates a key, marks the code used, and answers `{key, machine, kind}` once. A wrong, expired, used or unapproved code gets the same answer, so that nothing says which. Failed exchanges are counted for the whole server: after ten in a minute every exchange answers 429 until the minute is over, so that a code cannot be guessed (60 bits, 15 minutes, once, ten tries a minute: out of reach).
5. **A key is bound to its machine, and the ingest refuses the rest.** The account of an enrolled machine is the one in its row. A batch that names another machine is refused with 403 and a problem that says which machine the key belongs to. A `Collector` account that belongs to no machine (a hand-made one) is refused too, unless the setting `Ingest:RequireEnrolment` is turned off, which is for a sandbox and for the day before every machine is enrolled; the default is on. This closes the limit that [0025](0025-the-collector-is-a-service-per-machine-enrolled-by-a-code-and-configured-from-the-server.md) §3 accepted.
6. **The heartbeat.** At the end of every pass, even a pass that sent nothing, the collector calls `POST /api/v1/ingest/heartbeat` with `{version, passEndedAt, pendingLines, error}` (`error` is null or a short sentence, with no path and no content). The server takes the machine from the key. A batch also counts as a sign of life. A heartbeat from a key of no machine is refused.
7. **The states are computed from facts, with two settings.** `Collectors:OnlineWithinMinutes` (5) and `Collectors:SilenceAfterMinutes` (30). From the facts (revoked or not, last seen, kind, the last error): **refused** (the key was revoked), **waiting** (enrolled, never seen), **failing** (the last pass reported an error), **online** (seen within the first setting), then for an `intermittent` machine **away** (asleep or off: not an error), and for an `always-on` machine **silent**. A pure function of those facts and the clock, so that it is tried without a clock.
8. **The health is one mechanism.** A readiness check `collectors` (D-13, F-HLT-01) is degraded, with a reason code, when an `always-on` machine has been silent longer than the second setting (`collector-silent`) or reports an error (`collector-failing`). An `intermittent` machine never degrades it. The page and the check share the one function of §7.
9. **Revoking** a machine disables its account and revokes its keys; the row stays, as **refused**, so that what it wrote can be found and the name is not taken again without a person.
10. **The rights.** `collectors.manage` (adds, approves, rejects, revokes; `Admin` only) and `collectors.request` (asks over MCP; `Assistant` and `Admin`). Seeing the machines needs `conversations.read`, as before (ADR 0024 §3).
11. **The collector** gains `enroll --server URL --code CODE [--machine NAME]`: it exchanges the code, writes the key to a file only its user can read and a small bootstrap file (server, machine) beside it, and `run` and `once` find them without flags. The key is also accepted from the environment or a `--key-file`. It sends the heartbeat at the end of each pass; a refusal of the key is reported as such and does not stop the loop.

## Consequences

- A leaked key writes only under the name of its machine, and what a revoked key wrote can be found: the account is recorded on each conversation (ADR 0024 follow-up) and the machine is a row.
- The ingest endpoint can be exposed (vertical 3) without the risk the reviewers raised four times.
- An existing hand-made `Collector` account stops working at the next start, unless `Ingest:RequireEnrolment` is off. It is written in the release notes and in `docs/collector.md`.
- A code is typed by a person: the alphabet and the grouping are for that.
- The limit on wrong codes is for the whole server, so whoever can reach the endpoint can keep a person from joining a machine for a minute by sending ten wrong codes: a nuisance, not a way in, and the price of not trusting an address behind a proxy.
- Not here: installing the program as a service (the next vertical), the configuration from the server, a second key to read memory (Q-26), the notification of an alert (Portarr raises it, Q-38).
